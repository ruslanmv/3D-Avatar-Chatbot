      For AI coders

      Start at quality-lab/README.md. Everything on this page is plain JSON under quality-lab/data/: read index.json, then each run file it lists. 

      # run the lab against real routes (app running: npm start)
OLLABRIDGE_PAIR_TOKEN=… node tools/qa/character-lab.mjs --routes free-best,free-fast --langs en,it

# publish the report here (rescored with the current scorer)
node tools/qa/lab-publish.mjs tmp/character-lab/<report>.json --id <yyyy-mm-dd-name> --label "…"

# after changing the scorer
node tools/qa/lab-publish.mjs --rescore-all
npx jest tests/quality-lab.test.js tests/private-world/character-scorer.test.js

      Work queue

      Every issue the audit found, failures first. A failure is something the app would get wrong; a warning is something a place cannot do yet. Fix one, regenerate, and it leaves this list.

        Create a new space

        The pipeline that already exists, in order. Each step names the tool or file that owns it; the audit checks the ones marked ●. Full guide: docs/engine/AI_CODER_START_HERE.md.

        1. Source the art. CC0 or Apache-compatible GLB/glTF, textures ≤ 1024 px; record provenance in assets/vr-worlds/PROVENANCE.md.
        2. ● Add the world to assets/vr-worlds/worlds.json: id, title, tiers, measured triangles, light, scene: {src, at, turn}; a place also gets place, rating, category.
        3. ● Find the clear spot by raycasting, not by eye (?vrWorld=<id> shows it on the desktop).
        4. ● Phone stand-in if over the phone budget: a recipe in tools/vr/playground-subsets.json, cut with node tools/vr/subset-scene.mjs, added as <id>-light with lightFor.
        5. ● Measure spots: targets in tools/vr/spot-targets.json, then node tools/vr/measure-spots.mjs <scene>. Only verified spots are offered.
        6. ● Preview: node tools/vr/render-place-previews.mjs <id> (640×480 WebP ≤ 60 KB).
        7. ● Interactions (optional): a venue template in PlaygroundTemplateCatalog.js (≤ 4 actions); a private room also needs its config in assets/vr-worlds/private/.
        8. Comfort and tests: no prop within 1 m of the person or between you (●), npx jest tests/vr-worlds.test.js tests/vr-places.test.js tests/quality-lab.test.js.
        9. Regenerate the audit: node tools/qa/world-audit.mjs, then run the browser checks below and record what you saw in the commit.

        Checks you run

        What the audit cannot see. Each is a real tool in this repository; headless Chromium is simulation, never frame-rate or device evidence.

        Question Run Evidence type
        Does the place look right, with her in it? node tools/vr/render-place-previews.mjs <id> browser render
        Can she stand there, seen by the camera, in VR clearance? node tools/vr/measure-spots.mjs <scene> raycast on the real GLB
        Does entering VR start, show the card, hand over? npm run vr:entry-scenarios IWER simulation
        Is the VR panel readable? npm run vr:panel-shot browser render
        Does Private's card keep her face, chips and End visible? node tools/qa/private-ui-shots.mjs browser layout at four sizes
