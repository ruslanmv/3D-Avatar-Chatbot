# Adult experience configuration (AX1–AX5)

Private's style, intensity, ceiling and content capability are four separate
things. `src/features/together/PrivateExperienceProfile.js` (boot list before
TogetherCapability) owns style data and capability resolution;
`docs/engine/NEXUS_ADULT_EXPERIENCE_ARCHITECTURE.md` is the design and
`docs/qa/NEXUS_ADULT_EXPERIENCE_GAP_REPORT.md` the audit.

- **Intensity is still only ConsentFlow's**, moved only by the person. The
  ceiling installed on ConsentFlow is min(style, capability): it only narrows.
- **Content capability** is the lowest of the provider's tier (NEXUS default
  `sensual` for every provider; a deployment may name one) and the site's tier
  (`window.NEXUS_ADULT_EXPERIENCE_CONFIG`, set by the deployment, never storage
  or a setting). Nothing above `sensual` without `blackboard.adultVerified`. No
  build sets the config, so every build behaves as before.
- **Undeclared, NEXUS adds no content rule of its own** (an earlier product
  decision, pinned in `tests/behavior/private-register.test.js`); she is told
  only how to meet a boundary in her own voice. A declared tier is stated.
- **Mature** (fourth step, "Intimate" in nine languages) is offered only where
  the capability reaches `mature`; `PrivatePace` and the register now go to 4.
- **Truth and care are not configurable (AX6).** A sincere "are you an AI?" gets
  a truthful answer (unprompted disclaimers stay forbidden, P22).
  `PrivateExperienceProfile.wellbeingConcern` checks the person's own turn (en,
  it — the app, never the model): the session enters care mode for the rest of
  the evening. In care mode:
    - the level eases through ConsentFlow's soft-exit word
    - `_speak` is silent
    - the prompt is care-only, with 700 tokens
    - the app shows a fixed `care.notice` in the person's language (all nine
      packs)

    Never let a capability, style or tier switch any of this off.
    `docs/qa/NEXUS_AI_INTERACTION_REVIEW.md`.

- **Length follows the turn** (1 / 3 / 4 sentences), still a stated hard limit
  repeated last (P22's fix kept).
  `tests/private-world/adult-experience.test.js`.
- **A style is heard and seen, not only read (AX7).**
  `src/features/together/PrivatePresentation.js` (boot list after the profile)
  applies `presentationFor` through owners that already exist: `adjustVoice` in
  both `speakText` paths and lip-sync (≥ 0.8 × the person's rate, slower per
  step), a resting `happy` on the VRM (0.10 + 0.04 per step, ≤ 0.32) and the
  room's light once at start. BehaviorEngine, AnimationManager and the companion
  actuators settle to `restingExpression()` instead of `neutral` — clearing to
  neutral wiped the mood after her first line. `state().applied` says `false`
  for an owner that was missing. Gaze is declared, not applied. Care overrides
  it; stop resets it. Mature has its own beat pool. Contract:
  `docs/engine/NEXUS_EXPERIENCE_PROFILE_CONTRACT.md`;
  `tests/private-world/presentation.test.js`.
- **Character Quality Lab (AX8).** `tools/qa/CharacterQualityScorer.js` (pure,
  QA only, not in the boot list — kept out of the engine tree so the parity
  harness stays clean) scores a reply against Private's own rules, the language
  and repetition. `tools/qa/character-lab.mjs` drives the real page against a
  real OllaBridge route in EN and IT, records the served model (routes are
  aliases: one run saw three backends), latency, usage and the AX7 measurements.
  Token from `OLLABRIDGE_PAIR_TOKEN` or `--token-file`, never printed. Results:
  `docs/qa/NEXUS_CHARACTER_MODEL_EVALUATION.md`; gates:
  `docs/qa/NEXUS_PREMIUM_RELEASE_GATES.md`.
- **The Quality Lab site (AX9) is where lab results live.** `quality-lab/`
  (static, served at `/quality-lab/` by `npm start`; README is the agent's start
  page) shows every published run: scores, served models, replies, presentation
  and human reviews. Publish a report with
  `node tools/qa/lab-publish.mjs <report> --id … --label …`; after any scorer
  change run `--rescore-all` — `tests/quality-lab.test.js` fails if a stored
  score is not the current scorer's. Never hand-edit a run file.
- **The Quality Lab has a 3D area (AX10).** `?area=3d` shows
  `quality-lab/data/3d/worlds-audit.json`, generated by
  `node tools/qa/world-audit.mjs` from `assets/vr-worlds/` through VRWorlds' own
  `allowedOn`/`resolveFor`/`comfortProblem`: each world's desktop, mobile and VR
  availability, triangles against the phone budget, preview, spots (with scene
  hash), chips, and a work queue. Change a world and regenerate in the same
  commit — the test runs `--check` and fails on any `fail`.
- **The Quality Lab is the research hub for the open world (AX11–AX12).** A
  third area, `?area=atlas`, maps Nexus as regions of zones
  (`quality-lab/data/atlas/atlas.json`, the one hand-written data file) for
  desktop, mobile and VR — AR is out of scope for now. `world-audit.mjs` also
  writes `atlas-audit.json`: per-zone readiness from the 3D audit, what is
  walkable from home per device, and the gateway zones that cut the map.
  `node tools/qa/new-zone.mjs` starts a zone as a validated brief.
  `quality-lab/data/hub.json` (`tools/qa/hub.mjs`, called by the other tools) is
  the first file a session reads: ranked next actions, each with why, command
  and files. Phases and gates: `docs/engine/NEXUS_OPEN_WORLD_ROADMAP.md`.
- **The lab is also an MCP server (AX13).** `.mcp.json` registers
  `nexus-quality-lab` → `tools/qa/lab-mcp.mjs` (stdio, dependency-free — do not
  add the SDK, it would change the lockfile for every install). Ten tools over
  the same generators: status, next actions, worlds, one world, atlas, score a
  reply, recorded replies, new zone (dry run by default), regenerate, check.
  Stdout is protocol only; a test drives it end to end.
